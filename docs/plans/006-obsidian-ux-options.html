Obsidian for BB · Chosen direction · Not implemented yet

Connect a vault.
Let BB use your notes.

BB can read and edit the whole connected vault. No folder permissions, read-only switches or confirmations before saving.

One simple choice: which vaults to connect. Everything in a connected vault follows the same read/write model.

Setup

  1. In BB's iCloud settings: connect Apple, choose the vault folder and enable sync. Wait for its first successful sync.
  2. In Obsidian settings: connect the synced vault by name. That's it—no second permission screen.
  3. In chat: ask BB to find, read or change your notes.

Add more vaults the same way. BB identifies each source and edit by vault and note, so identically named notes don't get mixed up.

Everyday use

The same applies to assistant-written additions, new meeting notes, task edits, tags, aliases and other properties. BB does the requested work, then says what changed.

Reliability underneath, not more steps for you

  • Don't overwrite a newer edit. Check the note version and reread if it changed. No new confirmation step.
  • Don't collide with sync. Coordinate local saves with iCloud's file operations.
  • Don't duplicate an uncertain save. If a reply is lost, inspect the recorded outcome instead of blindly repeating the edit.
  • Keep a recovery copy. Preserve the previous version before replacing a note, without adding a recovery dashboard.
  • Say where it was saved. A local save or later sync run isn't proof that the phone received the change.

Whole-vault access removes permission controls, not file-format limits. The first implementation handles Markdown notes and properties throughout the vault, including nested and hidden folders. It doesn't execute plugin code or interpret attachments. Paths still cannot escape the connected vault.
