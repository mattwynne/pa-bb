# Indexed link evidence for GTD

**Recommendation.** Keep one Obsidian-owned vault index. Use its published paths to answer immediate-child and link-candidate questions, and its parsed frontmatter to answer an exact-note property question. Let GTD choose the owning note, interpret its lowercase `area` property and assign the Area ID. The existing Area projection already resolves from memory on the authorized indexed route. The work is to expose the right facts and remove unnecessary discovery from the consumer.

## What runs today

| Entry point | Actual work |
| --- | --- |
| GTD list RPCs and agent tools | `Projects.list` / `Areas.list` select an `ObsidianBackend`. On a new inventory, `readInventory` calls Obsidian status and, for a selected nested root, `vaultLocations`. It drains recursive `listProperties` pages selecting `type,status,title`, even for supporting notes. Metadata-only property projection already uses the index on eligible sources. |
| Folder membership | GTD also calls `listChildren` on the configured folder and on recognized first-level project status containers. This RPC already returns immediate directory and Markdown names, including empty directories. It dispatches to the files adapter. The direct adapter opens and enumerates the directory on each call. Without children support GTD marks coverage partial. |
| Project relationships | After choosing sibling note or immediate README ownership, GTD sends owner paths in groups of up to 50 to the GTD-only `projectAreasFromFrontmatter` RPC. It checks the version, frontmatter-only marker and declaration key, then supplies the key on the request. Folder-only projects have no declaration. The producer reads the selected owners’ properties and constructs candidate sets. GTD stages assignments and drops them on a failed relationship RPC. `areaId` is the exact target. Presentation separately maps nested targets to the enclosing top-level Area. |
| Obsidian agent link tool | `obsidian_resolve_link → Obsidian.resolve` reads the source note, parses the reference, lists Markdown paths for the connected mirror, and calls the normal note/section read on a unique match. Missing and ambiguous responses carry up to 20 candidate paths. A successful whole-note follow can participate in the normal read-proof protocol. GTD never calls this tool. |

The indexed relationship route acquires one lease per request, selects owners from the view and lazily constructs its lookup over note paths and directories. The live counterpart lists note paths, lists immediate Area directories, reads owner notes for frontmatter and checks specific parent directories for explicit nested folder targets. Its time, byte and directory limits can produce partial results. The revision/route/epoch returned across requests identifies continuing access authority. Separate requests can see different index publications.

## Evidence already in memory

Each published view contains directory paths (including empty and attachment-only directories), sorted Markdown note records, hashes, observation times, parsed properties, and path-qualified note/tree omissions. Optional bounded metadata includes aliases, links, headings, blocks, tags and tasks. Unsupported frontmatter and unavailable full metadata have separate warnings. A long body can exceed the metadata budget while leaving a usable `area` property. A parsed link occurrence supplies text and location, not a resolved destination or evidence that the occurrence declared an Area. Plain YAML paths need not appear among the parsed links at all.

Exact path existence, immediate parent/name, object kind, basename collisions and selected properties can all be derived from these records. The view has no note bodies, stored target graph, guaranteed metadata for every note, or GTD owner/Area mapping. Start with bounded scans of the immutable view. Measure repeated per-link scans before considering publication-time lookup maps and account for their memory if justified. Discovery of nested vault locations currently performs a separate marker search; distinguish that setup/access cost from inventory data reads.

## Synthetic declaration trace

Use source `Life/Projects/Plan.md`, selected root `Life` and Area folder `Life/Areas`. The fixture has notes `Life/Areas/Finance.md` (heading Budget), `Life/Other/Finance.md`, and `Other/Finance.md`, plus directory `Life/Areas/Empty`. Each input below is the string value of the owner's YAML `area`. The two columns show current behavior exercised against the service with synthetic files and the Area matcher respectively.

| Declaration | Generic agent follow | Current Area result |
| --- | --- | --- |
| `Finance` | Ambiguous across three notes | Two notes within Life compete, including the non-Area note. Unresolved. |
| `Areas/Missing` | Missing | Missing within Life. Unresolved, complete evidence. |
| `Areas/Empty` | Missing | Resolved directory ID `Life/Areas/Empty/`. |
| `[[Areas/Finance\|X]]` | Missing at mirror-relative path | Display text stripped. Resolves to `Life/Areas/Finance.md`. |
| `[[Life/Areas/Finance#Budget]]` | Reads the Budget section | Fragment disqualifies an Area declaration. Unresolved. |

Both matchers decode percent escapes and fold case for bare note names. A display alias after a pipe is syntax; neither matcher looks up a note by its YAML aliases. Explicit note paths match case-sensitively, with optional Markdown extension. Dot-relative paths use the source directory. The Area matcher additionally anchors unprefixed slash paths to the selected root, accepts already-prefixed paths and fences root escapes. Generic follow supports embeds, same-note heading/block references and selected text. External references and malformed encoding raise errors there; Area declarations leave the project unassigned.

For Area assignment, a bare folder name competes only if it is an immediate Area directory without a same-path sibling note. Bare notes compete throughout the selected root before GTD tests Area membership. Explicit nested directories are legal. For a note/folder pair the note wins even with a trailing slash in the declaration. A list resolves only when every element uniquely names the same target. Missing key, null, blank scalar or empty list means no declaration. Non-string entries, blank list members, more than eight entries or strings over 1024 characters are unresolved. Body text, old `areaId`, capitalized keys, and supporting notes supply no fallback. Malformed owner frontmatter is a coverage problem; a well-read but ambiguous declaration alone is not.

## Implementation sequence and ownership

1. **Obsidian — immediate children.** Keep the existing one-folder `listChildren(vaultId, folder)` wire shape. On the eligible route, select entries whose parent equals the requested folder, preserve kinds, ordering and output bounds, and check the folder itself exists. A missing or unreadable folder must remain distinguishable from an observed empty directory. Mark coverage partial for omissions that could hide immediate entries (including an omitted ancestor tree), and for clipped output. A malformed property on a known child does not hide its name. Keep authorized live enumeration on supported older sources.
2. **Obsidian — owner frontmatter.** Supply a bounded exact-note read taking one path and requested fields and returning property evidence, with explicit missing/unsupported/partial outcomes. Reuse the existing property parsing, value validation and projection where compatible. Preserve the distinction between an observed absent field, an absent README, and an unreadable note. The recursive property RPC serves existing callers. Its 4096-character projection budget can reject a valid eight-link declaration; test this boundary and preserve usable title/status when only relationship evidence exceeds a limit.
3. **Obsidian — link target evidence.** Factor reference parsing and path matching from content retrieval. Provide a plugin read for one source path and one reference in a selected root. Return bounded target evidence (kind, canonical path, match status, completeness), sufficient to distinguish missing, ambiguous, unsupported and incomplete. For explicit paths report the matching note and/or directory; for bare names report note uniqueness over the selected root and the normalized basename. GTD can combine that evidence with immediate Area children for its bare-folder rule. Preserve fragment/embed information so the consumer can decline those forms. Obsidian handles decoding, normalization, root checks and basename comparison once. Keep generic agent follow’s public content/section and read-proof behavior. Its candidate discovery can reuse the matcher in mirror-wide note mode; live target reading remains necessary when returning content. Treat any change to its current single-candidate-on-incomplete-list behavior as a separate compatibility decision.
4. **GTD — build inventory from immediate entries.** Enumerate the configured Projects folder and its recognized status containers one folder per call. Prefer an immediate sibling Markdown note, otherwise inspect the project folder for its exact README (or probe that exact path). A folder with no owner keeps its slash ID and defaults. An invalid or omitted sibling never licenses borrowing its README. A README-owned project keeps its slash ID and distinct notePath. Status containers override owner status. Enumerate Areas at one level with note/folder pair precedence and no status grouping. Request title/status/area only where used. Parse declarations in GTD, resolve each valid string, apply the candidate rules above, require a single in-scope target for all values, and preserve exact areaId and enclosing-Area presentation. Supporting notes must generate zero property or link requests.
5. **Roll out producer first.** Add a narrowly versioned consumer capability, with a distinct method or strict request marker for new semantics. Keep the old strict response shapes and both Area projections for existing clients. Test the GTD switch against an old producer and a rollback between discovery and use. Select the current verified frontmatter-only route when new capabilities are absent at negotiation. If even that contract is unavailable, retain the existing partial/unassigned behavior. Never retry a denied or mid-read failing route through weaker access. Remove compatibility code and the GTD-specific producer policy only after supported consumer versions no longer call it. No vault migration is required.

These operations have different consumers, arguments and failure boundaries. Start with single-folder, single-owner and single-link reads. Keep existing inventory limits, cancellation and partial-result handling. Measure call counts and latency on synthetic inventories within those limits before proposing batching, pagination, broader scopes or another cache.

## Access, consistency and acceptance

Use one authorized publication per indexed operation. Cold acquisition waits for initial publication. Healthy refreshes can leave an older complete publication visible. Revalidate connected revision, route, directory identity and lease before releasing results, and close leases on every exit. Preserve caller restrictions when replacing the GTD-only surface. A query root limits matching and does not grant access. Verify the source path belongs to the selected root. Follow current routing for ready direct sources with negotiated grant v1, older direct sources without the capability, and pending/conflicted legacy logical sources. An unconfirmed capability, denied grant, replaced directory, failed refresh or revoked connection cannot authorize a weaker read. Local availability governs reads while cloud sync is paused or disconnected.

Carry the current authority check through a multi-call inventory (e.g. expected authority on new calls, checked again before returning assembled evidence). Do not infer one shared generation from an epoch. If access changes, discard affected buffered evidence. A known partial owner or clipped folder can retain independent confirmed results; mark GTD coverage partial. Current indexed Area matching conservatively treats any omission inside the selected root, or an omitted ancestor tree, as unsafe for target uniqueness; a missing Area folder also makes it partial. Preserve that conservative rule initially. A lone generic note candidate from an incomplete catalog is insufficient for GTD assignment. Keep failure logs bounded to operation and category.

**Evidence and open decisions.** The working checkout’s focused synthetic suites passed 83 Obsidian and 29 GTD tests. The existing warm relationship test already forbids five local I/O methods across requests. The proposed end-to-end inventory gate extends that coverage. Before finalizing wire schemas, settle how unchanged strict child replies participate in authority continuity, whether valid large property lists need a different bound, and whether cross-call publication drift is acceptable when a note/folder pair changes between discovery and owner lookup. If coherent results require it, detect and report change or retry a bounded read before designing a shared snapshot session. Measure nested-root validation separately before promising a traversal-free *entire* inventory. No production latency or live-vault verification was part of this investigation.
