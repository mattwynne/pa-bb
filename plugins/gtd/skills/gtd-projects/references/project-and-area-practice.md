# Define and review GTD projects and areas

## Clarify the commitment

- A **project** is a desired outcome the user is committed to completing within about a year that takes more than one action. One concrete action belongs on a Next Actions list. An idea the user may pursue belongs on Someday/Maybe. For a longer-term goal, identify the next meaningful result the user can commit to finishing within about a year.
- An **area of focus** is an ongoing responsibility or sphere of life or work with a standard to maintain. Name the responsibility at a level the user can review over time. A responsibility can be healthy without an active project. A gap in the standard may call for a single action, a change in routine, or a project.
- In David Allen's *Horizons of Focus* example, **Finance** is an area at Gracie's Gardens and **get the books current** is a project. An illustrative standard is “The books are reconciled monthly.” An illustrative completion criterion is “All transactions through the agreed cutoff are recorded and reconciled.” Allen also names health, finances and family as personal areas in his Milan keynote.

## Create or clarify a project

1. State the finish line in the title. Use a verb that points to completion or describe the achieved state. For example, “Bring the books current through September” or “Books reconciled through September.” If the right course is unknown, a decision can itself be the outcome, such as “Decide whether to repair or replace the washing machine.”
2. Ask what would have to be true to call the project done. The title can be enough. Add a short “Done when” statement or checklist if the boundary is ambiguous. Use observable evidence such as a decision recorded, approval received, a deliverable usable by its intended audience, or a measured target reached. Include a deadline or number when it changes what counts as success.
3. Identify the next concrete action the user can take now, or what they are waiting for if someone else owns the next move. Keep future steps in project support until actionable. If the user has an action list, use it when asked to record the next action.
4. For a project that needs more planning, use Allen's **Natural Planning Model** in order: define purpose and principles, envision the outcome, brainstorm, organize, and identify next actions. Purpose is why it matters. Principles guide choices. The outcome describes the result. Completion criteria tell you how to recognize it. Use as much detail as the project needs.

## Review projects and areas

- During a project review, check whether the desired outcome still reflects the commitment, whether the completion criteria have been met, and whether there is a current next action or Waiting For. If the commitment changed, clarify the new outcome or propose the appropriate disposition. Treat partial evidence as an open question. GTD uses the Weekly Review to keep the project list current.
- When creating or reviewing an area, identify the enduring responsibility, the standard the user wants to maintain, and observable signs it needs attention. Check whether the standard still fits and whether current routines, actions or projects cover any gaps. Review periodically and when responsibilities change. Existing projects can help reveal which areas the user is already responsible for.
- Present review findings and proposed edits using the user's wording where possible. Keep uncertainties explicit. Apply changes when requested and preserve existing backend conventions, identities and associations.
