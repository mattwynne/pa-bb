# First native paragraph-bold candidate (unregistered)

This is an isolated implementation, not a serving registration, live-provider
proof, rendered-UI acceptance or additional scored coverage. `server.ts` does not
register it. The closed [first literal replacement profile](replacement.md) now
reuses this same protected path. Suggestion/collaboration editing, shared-drive
boundary support and multi-stage execution are not supplied.

## Actual composition

`docs-semantic-apply-tools.mjs:createBoldApplyHandler` returns unregistered native
apply/status definitions. The SDK schema accepts only account, existing operation
UUID and immutable plan hash. The handler resolves and verifies the actual
connected Google subject, uses host thread/signal, and uses the existing native
`docs-format-approval` renderer through real `bb.ui.requestInput`. No agent-supplied
approved/force/resource/body fields are accepted. The full sealed paragraph,
revision, selected command and effective-before bold/provenance/source are visible
and hashed. An invalid, closed, expired or declined choice cannot submit. The
existing live Docs content opt-out records distinct standing content consent;
it never becomes a fabricated owner decision or another route's exemption.

`bold-apply.mjs` collects the actual Reader/draft/context/full-before seal path.
`sealForApply` atomically discriminates a fresh winner from an existing receipt.
Only the fresh transaction winner receives a private opaque in-process capability.
A persisted dispatch UUID is an attribution fact, NOT that capability. Every
mutating stage entry binds the original subject/account/thread/head and capability.
All existing, duplicate, reopened and seal-only records return facts, not a new
first-dispatch right. No retry, rekey, resume, rollback or force-unlock is offered.

## Final cut and one invocation

Settings `get/onChange`, supported disposal hooks and real account mutation entry
points supply observed authority epochs. Mechanical same-identity token refresh
is not reconnect. The actual prepared adapter finishes identity/tokeninfo/scope
checks and captures fixed endpoint, exact compiled bytes/hashes and private token.
No token enters a receipt, ledger, review payload or diagnostic. Native batch and
tokeninfo requests refuse redirects; a 307/308 is not permission to replay a POST.

The final intent transaction rechecks current account/head/full unchanged before,
exact semantic rights and fresh SQL-authoritative blockers/known result IDs.
It commits unknown BEFORE invocation. Synchronous epoch/signal/deadline and exact
SQL checks then consume the one-use dispatch gate immediately before non-async
`dispatchOnce`; there is no application await between intent and fetch. A genuine
observed veto can record known-not-sent only while its original capability remains
uninvoked. Once the gate is consumed, even that original capability cannot unlock
unknown as a pre-invocation veto. Remote-only changes are not promised zero POST.

## Durable response, verification and retention

Migration13 appends immutable stage events/evidence; migrations0–12 remain exact.
Response/stage/coordinator facts, evidence and remaining future credit change in
one synchronous transaction. Actual stored charge replaces precharged reservation
instead of demanding the same capacity twice. Raw reply decoding stays 16KiB;
reply-envelope overhead is bounded separately. The full after-model is bounded
at 1MiB. Existing evidence/writer quotas are unchanged.

Attributable document/reply/required-revision ACK is saved before any GET, through
original dispatch lineage even after cancellation, account removal or disposal.
Disposal synchronously invalidates authority and drains active operations before
storage closes. ACK-storage failure means durable unknown and zero readback.
Unexpected save/suggestion/reply facts stay explicit held outcomes. A fresh actual
full read must match the verified subject, document and the ACK's own revision;
equivalent content at another revision is not own-effect verification. Independent
`compareParagraphBold` receives retained full actual before and actual full after,
never compiler-generated expected content. Only matched permitted completion
normally releases claims. Read failure/mismatch preserves ACK and held claims.

Unknown plus observed matching remains unknown/held; read-only observation never
invents ACK or changes history. Status always reports this-call mutation count0.
Execution refs retain original evidence past ordinary snapshot/pin expiry and
sweep without renewing normal read/planning authority. Frozen seal-only records
never auto-activate. Fixed safe stage diagnostics never include provider content,
credentials or raw exceptions; diagnostic failure cannot change durable facts.

Closed SDK/file-SQLite and real loopback subprocess tests are engineering proofs,
not live delivery. Rendered desktop/narrow/keyboard/deferred-state review and
independent review remain separate gates before any activation decision.
