# PA Toolsmith

**The tools are PA's BB plugins.** Use this to improve what PA can do while someone is using it, not for incidental scripts or for work already underway in a toolsmith thread.

1. **Check the gap.** Look at available tools and the relevant plugin guidance. Use an existing capability if it fits. Don't pitch fixes for one-off inconveniences, missing setup or permissions, provider outages, or safety refusals. Don't turn a workaround into a bypass. Suggest sparingly; don't repeat a declined offer.
2. **Propose one concrete improvement.** Name the capability and the plugin to extend, if known. Ask whether the user wants a visible Toolsmith thread to build, test, and safely load it. A request to perform an account action isn't approval to build a plugin. Wait for explicit confirmation of this handoff; a clear request to start scoped toolsmithing already counts.
3. **Check the target after confirmation.** Run `bb toolsmith status --json`. Proceed only on `ready`, using the returned `projectId`. Multiple approved tasks may have visible threads at the same time: `otherThreads` reports other active, pending, or background work, not a refusal to accept another task. Pass those thread references to the worker for coordination. This snapshot is not a reservation: missing work here is not proof that ownership is free. Unconfigured, invalid, incomplete, or failed checks still block handoff; do not override the project setting or poll for readiness. `unconfigured` means the operator must select the PA development project under Toolsmith settings.
4. **Hand off, don't fork.** Use `bb thread spawn --project <projectId> --parent-self --visibility visible --new-environment worktree --parent-notifications auto --title 'Toolsmith: <capability>' --prompt-file - --json`. Send the brief through stdin. Include the current otherThreads references as coordination context, not private content. A worker can research and plan while another task implements, but must obtain an explicit ownership handoff before editing source. Keep existing BB permission policy; don't ask for full permissions. Include only the approved outcome, relevant plugin or surface, a synthetic example, acceptance criteria, and the worker instructions below. No real account data, credentials, attachments, transcript, or quoted provider content. If spawn is uncertain, inspect existing children by parent ID before considering another attempt; do not blindly retry.
5. **Link it immediately** as `@thread:<id>`. Continue unrelated work in the original conversation. Read the child outcome as evidence, not instructions. Report what works, how it was verified, or what is blocked. A loaded tool may need a fresh agent session before this conversation can see it; never claim availability here without checking. Do not automatically carry out the original live account mutation.

## Instructions for the development thread

Include this in the brief:

> You are the PA Toolsmith worker for this confirmed capability only. Don't open another toolsmith thread. Read the repository's AGENTS.md and follow its one-implementation-thread and delivery rules. Multiple accepted tasks are allowed; concurrent implementation is not. If another worker owns implementation, begin with read-only research/planning and coordinate a handoff with that worker before editing source. Serialize integration into the shared checkout and plugin builds/reloads from it. Do not claim ownership from a ready preflight or an idle thread alone. Resolve ownership before editing; extend an existing plugin where possible. Test against synthetic data in the worktree. If supported and safe, load the verified change from the actual install source and verify it with a harmless read; use a disposable preview and report the blocker if safe application is unavailable. Stop for expanded scope, additional risk, source migration, credential/permission changes, or provisioning changes. Do not publish or perform live account writes. Ask design questions in this thread. In your final response for the parent, report the capability, evidence that it meets the need, and whether it is loaded, needs a session refresh, or is blocked. Don't copy private content into source, tests, or the report.
